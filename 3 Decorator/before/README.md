# 결제 버튼 핸들러 (데코레이터 패턴 연습)

헤드퍼스트 디자인 패턴 세미나에서 배운 **데코레이터 패턴**을 적용해 보기 위한 연습 프로젝트입니다.
이 저장소의 현재 코드는 **패턴 적용 전** 상태이고, 이 코드를 데코레이터로 리팩터링하는 것이 목표예요.

## 실행 방법

빌드나 설치가 필요 없어요. `before/index.html`을 브라우저에서 열면 바로 실행됩니다.

## 파일 구성

```
before/
├─ index.html          화면 구조 (HTML)
├─ style.css           스타일 (CSS)
└─ js/
   ├─ utils.js         작은 도구 ($, sleep)
   ├─ logger.js        로그 패널 출력
   ├─ ui.js            화면 값 읽기, 버튼 모양 바꾸기
   ├─ payService.js    핵심 로직 pay() (감싸질 본체)
   ├─ handlers.js      클릭 핸들러 A/B (문제의 중심)
   └─ main.js          이벤트 연결 (시작점)
```

JS는 `<script>` 태그로 위에서 아래 순서대로 불러와요. 아래 파일이 위 파일의 함수를 쓰기 때문에 `index.html`의 로드 순서를 바꾸면 안 됩니다.

## 주제

결제 버튼을 클릭했을 때 실행되는 핸들러에 아래 부가 기능을 선택적으로, 그리고 **원하는 순서로** 감쌉니다.

- 클릭 로그 남기기
- 로그인 체크
- 중복 클릭 방지 (1.5초)
- 로딩 표시

핵심 로직은 `pay()` 하나이고, 나머지는 모두 이 함수를 감싸는 부가 기능입니다.

## 순서가 결과를 바꾸는 이유

같은 기능을 켜도 감싸는 순서에 따라 동작이 달라집니다.

| 순서 | 로그인 안 한 상태로 클릭하면 |
| --- | --- |
| A: 로그 → 로그인 → 중복방지 → 로딩 | 막혔지만 클릭 로그는 **남음** |
| B: 로그인 → 중복방지 → 로그 → 로딩 | 막혔고 클릭 로그도 **안 남음** |

## 직접 해볼 것

1. 로그인 체크를 켜고 로그인 상태는 끈 채로 버튼을 눌러 보세요.
2. 순서 A와 B를 번갈아 선택하며 로그 차이를 비교하세요.
3. 버튼을 빠르게 연타해서 중복 클릭 방지가 동작하는지 확인하세요.
4. 중복 방지를 끄고 연타하면 결제가 여러 번 실행되는 것도 확인해 보세요.

## 현재 코드의 문제점

- 순서를 바꾸려면 `handlers.js`의 `handleClickA`를 통째로 복사해 `handleClickB`를 만들어야 합니다.
- 기능이 4개면 가능한 순서는 24가지입니다. 함수를 24개 만들 수는 없어요.
- 새 기능(예: 재시도)을 추가하면 모든 핸들러를 열어서 `if`를 끼워 넣어야 합니다.
- `opts` 플래그가 늘어날수록 함수 안이 `if` 투성이가 됩니다.
- 순서가 늘어날 때마다 클릭 이벤트 쪽의 분기(`if (order === "A")`)도 함께 늘어납니다.

## 리팩터링 목표

- [ ] `payService.js`의 `pay()`를 건드리지 않고 부가 기능을 바깥에서 감싼다.
- [ ] 기능마다 감싸는 함수를 하나씩 만든다. (예: `withLog`, `withAuth`, `withGuard`, `withLoading`)
- [ ] 순서 A와 B를 **함수 복사 없이** 감싸는 순서만 바꿔서 표현한다.
- [ ] 새 기능을 추가할 때 기존 코드를 수정하지 않고 감싸는 함수만 추가한다.

## 참고

- 데코레이터는 억지로 쓰지 않는 게 좋아요. 이 예제는 **기능 조합이 많고 순서가 결과를 바꾸는** 상황이라 패턴이 잘 맞는 경우입니다.
- 적용한 버전은 `before/`를 복사한 `after/` 폴더에서 작업하면 비교하기 좋아요. 이때 `payService.js`는 그대로 두고, 감싸는 함수 파일(예: `js/decorators.js`)을 추가하면 됩니다.
